# 검증

아래 세 가지를 실행한다. 서로 독립적이므로 함께 돌린다.

```
flutter analyze
flutter test
python3 tools/check_docs.py
```

## 결과 다루기

- 셋 다 통과하면 통과했다고 알린다.
- 실패가 있으면 출력의 해당 부분을 그대로 보여 주고 원인을 조사한다. 이번 작업으로 생긴 실패면 고치고 다시 돌린다. 이전부터 있던 실패면 고치지 말고 그렇다고 알린다.
- 테스트를 지우거나 건너뛰거나 기대값을 결과에 맞춰 바꿔서 통과시키지 않는다. 테스트가 틀렸다고 판단되면 근거를 들어 사용자에게 알린다.
- 실행하지 못한 항목이 있으면 실행하지 못했다고 말한다. 통과로 치지 않는다.

## 이것으로 확인되지 않는 것

이 검증은 화면에서의 실제 동작, 기기 성능, 플레이의 재미를 확인하지 않는다. 그런 변경이었다면 무엇을 직접 확인하지 못했는지 함께 알린다.

게임 코드를 바꿨다면 `rule-reviewer` 에이전트로 기획과 구조 규칙에 맞는지 추가로 볼 수 있다. 기획서를 여러 개 고쳤다면 `doc-keeper` 에이전트로 문서 간 어긋남을 본다.
