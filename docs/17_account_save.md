# 17 계정과 저장

누구의 기록인지 어떻게 정하고, 그 기록을 어디에 남기는지 정의한다. 공간의 전체 구조는 [16 게임 공간 구조](16_game_structure.md)에 있다. 따로 표시하지 않은 항목은 모두 [제안]이다.

지금 구현은 기기 안의 파일 둘이다. `user://save.json`은 스테이지별 점수 순위, 클리어한 스테이지, 계정 종류(지금은 게스트뿐)를 담고, `user://settings.json`은 설정을 담는다.

**할 일**: 구글 계정(Google Play 게임 서비스) 연결. 개발 중에는 시나리오용 로그인 화면만 두고 그대로 지나간다. [확정] (2026-11-25)

## 로그인 방식

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| A 로그인 없음 | 기기에만 저장한다 | 서버와 개인정보 처리가 없다 | 기기를 바꾸면 기록이 사라진다. 온라인 순위가 없다 |
| B 게스트로 시작, 나중에 연결 | 처음에는 바로 시작하고, 원할 때 계정을 연결한다 | 첫 판까지 막힘이 없다. 연결하면 기록이 옮겨진다 | 두 상태를 모두 다뤄야 한다 |
| C 로그인 필수 | 로그인해야 메인 메뉴에 들어간다 | 모든 사람이 계정이 있어 온라인 기능이 단순하다 | 첫 화면에서 떠나는 사람이 생긴다. 서버가 죽으면 게임을 못 한다 |

B로 한다. [확정] (2026-11-25) 캐주얼 게임은 첫 판까지의 시간이 짧아야 하고, [16](16_game_structure.md)의 "서버가 없어도 끝까지 할 수 있다"는 원칙과 맞는다.

로그인 화면은 다음과 같다. [제안]

- 단추 둘: "Google Play 게임으로 시작", "게스트로 시작". 아이폰에서는 첫째가 Game Center가 된다.
- 게스트로 시작한 사람에게는 캐릭터와 설정의 계정 칸에서 연결을 권한다. 지역 하나를 깼을 때 한 번만 따로 권한다.

## 계정을 대는 곳

| 안 | 내용 | 비고 |
|---|---|---|
| A 스토어의 게임 서비스 | Google Play 게임 서비스와 Game Center. 로그인, 저장 맞추기, 순위표, 업적을 준다 | 우리 서버가 없다. 두 스토어의 기록이 서로 섞이지 않는다 |
| B 서버 서비스를 빌림 | Firebase 같은 것. 로그인, 저장, 순위를 우리가 짠다 | 두 스토어의 기록을 합칠 수 있다. 달마다 비용과 관리가 든다 |
| C 서버를 직접 만듦 | 점수 검증까지 서버에서 한다 | 판정이 결정적이므로 입력 기록을 다시 돌려 점수를 검증할 수 있다([08](08_scoring.md)). 일이 가장 많다 |

A로 시작한다. [확정] (2026-11-25) 아직 붙이지 않았다. 온라인 순위에서 속임수가 문제가 되면 그때 C의 검증만 더한다. 비용과 조건은 확인 전이다.

## 저장하는 것

저장은 세 덩이로 나눈다. 덩이마다 옮겨 다니는 범위가 다르다.

| 덩이 | 담는 것 | 계정을 따라 옮기나 |
|---|---|---|
| 진행 | 스테이지별 최고 점수, 별, 클리어 여부, 찾은 아이템, 도감, 지역 해금 | 옮긴다 |
| 캐릭터 | 이름, 얼굴, 레벨과 경험치, 고른 탈것, 가진 꾸밈과 소지품, 재화, 누적 기록 | 옮긴다 |
| 설정 | 소리, 진동, 민감도, 화질, 언어 | 옮기지 않는다 (기기에 딸림) |

- 기기 안의 스테이지별 점수 순위 20개는 지금처럼 기기에 남긴다.
- 저장 파일에는 판 번호를 둔다. 형식이 바뀌면 옛 판을 새 판으로 옮기는 코드를 함께 넣는다.
- 판의 중간 상태는 저장하지 않는다. 한 판이 3~5분이라 다시 하면 된다.

## 저장을 맞추는 규칙

기기의 저장과 계정의 저장이 다를 때는 하나를 고르지 않고 합친다.

- 스테이지별 최고 점수와 별은 큰 쪽을 쓴다.
- 클리어, 해금, 도감, 가진 꾸밈은 둘 중 한쪽에라도 있으면 있는 것으로 한다.
- 재화와 소모품은 마지막에 저장한 쪽을 쓴다. 합치면 두 기기에서 번갈아 써서 늘릴 수 있기 때문이다.
- 맞추는 때는 시작 화면, 결과 화면, 앱이 뒤로 갈 때다. 실패해도 게임은 이어지고 다음 기회에 다시 맞춘다.

## 개인정보

- 모으는 것을 줄인다. 계정 서비스가 주는 id와 플레이어가 정한 이름만 쓴다. 이메일, 연락처, 위치는 받지 않는다.
- 이름은 다른 사람에게 보이므로(온라인 순위) 길이를 제한하고 걸러 낸다.
- 설정에 "내 데이터 지우기"를 둔다. 기기의 저장과 계정의 저장을 모두 지운다. 스토어 심사에서 요구한다.
- 개인정보 처리방침 문서가 필요하다. 스토어에 올리기 전에 쓴다.
- 서버 주소나 키는 코드에 쓰지 않고 `.env`에 둔다(CLAUDE.md).

## 구현 구조

- 저장은 `src/meta/` 아래에 둔다. 지금의 `save_data.gd`를 진행, 캐릭터, 설정 세 덩이로 나눈다.
- 계정 서비스는 한 겹(`src/meta/account.gd`) 뒤에 둔다. 게스트일 때는 아무 일도 하지 않는 구현을 쓴다. 나머지 코드는 로그인 여부를 따지지 않는다.
- 저장과 계정은 판정(`src/sim`)에 닿지 않는다.
